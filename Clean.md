## Comment

Change the color of the comment.

- Comment if code cannot explain itself
- Code should explain itself
- Comment: unfortunate and needless
- Comment don't make the code clean and expressive, make the code to do
- Place the code right where the code is, not about a code in somewhere else.

## Names

The name should reveal the context of the problem being solved.

1. For variables

   - Reveal your intent in the name
   - A variable name should be proportional to the size of the scope it contains
   - Long scopes, longer variable names

2. For Functions
   - For instance, class variables or global variables can be longer.
   - As the scope of the function increase, shrink the name, because we are going to call them more.
   - If a function does a precise things, it can contains longer names.
3. For classes
   - Classes are the same

- Avoid redundant names, like `product, data,...etc.`
- Make sure the names of pronounceable
